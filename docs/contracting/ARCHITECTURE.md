# قطاع المقاولات — المعمارية والمراحل المقترحة

## المبادئ (من المواصفة، مطبّقة على منسق)
- **وحدة واحدة قابلة للتهيئة:** التخصص (مباني، خطي/طرق، MEP، تشطيبات، EPC، اتصالات، نفط وغاز، O&M) = قالب بيانات مُصدَّر `specialty_templates` (قالب WBS، وحدات، قوائم ITP، حقول مخصصة، آلة حالات، شكل المستخلص). ملف العقد (اعتماد 2020، مقاول 2024، FIDIC 1999/2017 أحمر وأصفر وفضي، NEC4، مخصص) = `contract_profiles` بنسب افتراضية قابلة للتعديل ومهل الإخطار.
- **القيم التنظيمية بيانات:** `regulatory_parameters {key, value, unit, regime (GTPL_1440|GTPL_1448|PRIVATE|ALL), legal_basis, source_title, source_url, effective_from, effective_to, status (draft|verified), verified_by, notes}` + `resolveParam(key, {date, regime})` ترمي خطأً واضحاً عند الغياب أو عند قيمة draft (لا قيمة افتراضية). الحساب بتاريخ الحدث ونظام العقد (تاريخ طرح المنافسة)، لا بتاريخ اليوم. وتظهر «المرجع النظامي المطبق وتاريخ سريانه» مع كل حساب.
- **إعادة الاستخدام أولاً:** القيود عبر `posting.ts`، الفواتير عبر `issueSalesDocument` وزاتكا فقط، الموردون والمشتريات والمخزون والآلات والموظفون كما هي.
- **ثبات المستندات:** المستخلص المعتمد والقيد والفاتورة لا تُعدّل؛ التصحيح بمستند عكسي. جداول الإضافة فقط بـ trigger.
- **البعد التحليلي:** المشروع = مركز تكلفة `kind = project`؛ ويُضاف لسطور القيود `wbs_id` و`cost_code_id` (أعمدة اختيارية، لا كسر).

## قرارات مطلوبة قبل C1
1. البعد: المشروع كمركز تكلفة + أعمدة WBS/بند تكلفة على سطور القيود (موصى به)، أم أبعاد مستقلة.
2. من يوثّق القيم التنظيمية: مدير المنصة لسجل عام تعتمد عليه كل المنشآت (موصى به)، أم كل منشأة لنفسها.
3. الترحيلات للأمام فقط كما في CLAUDE.md (موصى به) رغم أن المواصفة تطلب ترحيلات قابلة للتراجع.
4. نطاق أول دفعة: C1-C3 (موصى به) ثم «كمل» مرحلة بمرحلة.
