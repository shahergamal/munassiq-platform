# وحدة التصنيع: المرحلة 0 (الاكتشاف)

تاريخ: 2026-09-28. المصدر: قراءة الكود الفعلي (لا افتراضات). المرجع التنظيمي: ملف «وحدة التصنيع المتكاملة لبرنامج منسق في السعودية» (compass_artifact) + `docs/KSA_ACCOUNTING_ZATCA_RESEARCH.md`.

## 1. البنية القائمة (ثابتة بحكم `CLAUDE.md`)
| البند | الواقع | أثره على التصنيع |
|---|---|---|
| الخلفية | Node ≥22.18، TypeScript قابل للحذف يُشغَّل مباشرة، Fastify 5، `pg` بلا ORM، `zod` للتحقق | لا Prisma/Drizzle ولا BullMQ ولا decimal.js (يخالف الملف، والمشروع يفرض) |
| القاعدة | PostgreSQL، سلسلة migrations واحدة `db/migrations` (0001-0024)، RLS + `withTenantTx`، دوران `munassiq_app` و`munassiq_system` | كل جدول تصنيع: `tenant_id` + سياسة RLS + `tenant_is_operational` للكتابة |
| الواجهة | React 19 + Vite + TanStack Router/Query، RTL عربي فقط، CSS بمتغيرات `DESIGN.md`، `<dialog>` أصلي | لا i18n ولا LTR اليوم |

| مهام الخلفية | لا طابور: `setInterval` (تنظيف، قياس مساحة) و`setImmediate` لإبلاغ زاتكا مع مسح كل 5 دقائق | MRP والتقارير الثقيلة تُنفَّذ عند الطلب؛ زاتكا يحتاج عاملاً دائماً (قرار) |

## 2. القطاعات
- `sectors(key, name_ar, is_available)`: `manufacturing` موجود و`is_available=false`؛ التسجيل يرفضه ويحوّل لقائمة الانتظار. القاعدة الثابتة: **لا يُفعَّل قطاع بلا تنفيذ حقيقي.**
- لا توجد باقات `manufacturing-*` في `plans`، و`createTenant` يطلب `${sector}-trial`.
- **لا يوجد أي تقييد بالقطاع** في المسارات أو القائمة أو الأدوار: كل مسارات `routes/restaurants/*` تُسجَّل لكل منشأة، و`NAV` ثابت يُرشَّح بالصلاحية فقط.
- ما يُزرع عند الإنشاء: الوحدات القياسية (للمطاعم فقط)، تصنيفات مصروفات مطعم، دليل حسابات مطعم، حسابات الدفع.

## 3. ما يُعاد استخدامه وما ينقص (حسب مراحل الملف)
### المرحلة 1: الأساس المحاسبي — **موجود بنسبة كبيرة**
- موجود: دليل حسابات هرمي (`accounts` بـ `system_key`)، قيود لا تُعدَّل، فحص التوازن عند COMMIT، رفض الترحيل قبل `lock_date`، منع الترحيل على حساب رئيسي، `source_key` فريد (ترحيل idempotent)، قيد عكسي مرة واحدة، قيد افتتاحي بحساب وسيط، ميزان وقائمة دخل ومركز مالي وأستاذ وأعمار وإقرار ضريبة.
- ينقص: حسابات تصنيع (خام/تحت التشغيل/تام/قطع غيار/أعباء محمّلة/انحرافات/هالك غير عادي/استقطاع مستحق)، **مراكز تكلفة وأبعاد** (السطر يحمل فرعاً وشريكاً فقط)، **سنوات وفترات مالية** (يوجد تاريخ قفل وإقفال سنة ميلادية فقط)، ترقيم بلا فجوات لكل نوع مستند/فرع/سنة، معالج افتتاحي من Excel (ذمم بالفاتورة، مخزون بالدفعة)، Posting Rules قابلة للتهيئة (اليوم دالة ترحيل لكل عملية بحسابات بـ `system_key`).
### المرحلة 2: المخزون — **موجود بنسبة متوسطة**
- موجود: `stock_levels` بمتوسط مرجّح متحرك لكل موقع، `stock_movements` إضافة فقط، منع الرصيد السالب في القاعدة، تحويلات بحالة «في الطريق»، هدر، جرد دوري بقيد فروقات، دفعات وصلاحية وFEFO (0022)، باركودات متعددة، مواقع (مطبخ/مستودع/متجر).
- ينقص: نوع الصنف (خام/نصف مصنع/تام/خدمة/مستهلك/قطع غيار)، اسم إنجليزي، فئة ضريبية للصنف، سعر بيع، تتبع سيريال، FIFO بطبقات تكلفة، مواقع هرمية (منطقة/ممر/رف/خانة)، أنواع مستودعات (خام/إنتاج/تام/حجر جودة/هالك)، الحجز، نقطة إعادة طلب وكمية اقتصادية ومهلة توريد، **حساب مخزون واحد** (لا فصل خام/تام)، منع صرف المنتهي صراحة. الاسم في كل مكان «ingredient».
### المرحلة 3: المشتريات والمبيعات — **المشتريات جيدة، المبيعات ناقصة**
- موجود: طلب شراء ← اعتماد ← أمر شراء (اعتماد المالك فوق حد) ← سند استلام بالمقبول والمرفوض وسعر الفاتورة ← مرتجع ← دفعة مورد؛ تكلفة واصلة (شحن/رسوم موزعة بالقيمة)؛ فواتير ضريبية ومبسطة وإشعارات دائن/مدين بفئات S/Z/E/O وسندات قبض.
- ينقص: فاتورة مورد كمستند مستقل بمطابقة ثلاثية وتسامح، توزيع التكلفة الواصلة بالوزن/الكمية وبعد الاستلام، **الاستقطاع** (مقيم/غير مقيم 5/15/20%)، عرض سعر، **أمر بيع بحجز**، **إذن تسليم يُخرج المخزون ويقيد تكلفة المبيعات** (الفاتورة اليوم نص حر بلا صنف ولا مخزون)، قوائم أسعار، حد ائتمان، دفعة مقدمة 386. جدول العملاء يشترط الجوال (مصمم للكاشير).
### المرحلة 4: التصنيع — **غير موجود تقريباً**
- الموجود الوحيد: «الوصفات التحضيرية» (`prep_recipes`) و«دفعة إنتاج» (`production_runs`) تستهلك المدخلات بالمتوسط وتنتج بتكلفة = المدخلات ÷ الناتج، بدفعة وصلاحية، مستوى واحد، **بلا قيد محاسبي**، بلا عمالة ولا أعباء ولا هالك ولا حالات.
- ينقص كله: مراكز عمل، مسارات تشغيل، BOM متعدد المستويات بإصدارات، أوامر تشغيل بحالات، WIP، عمالة وأعباء محمّلة، هالك عادي/غير عادي، منتجات ثانوية، طرق التكاليف، MRP، جدولة، جودة، صيانة.
### المرحلة 5: زاتكا — **موجود ومختبر بمحاكٍ**
- موجود: CSR secp256k1، UBL 2.1 بشكل قانوني، XAdES، QR بـ 9 وسوم، تسجيل ذاتي بـ OTP واختبارات الامتثال الستة، اعتماد الضريبية وإبلاغ المبسطة، سلسلة ICV/PIH بـ trigger لا يرجع، تشفير AES-256-GCM للمفتاح، 388/381/383.
- ينقص: 386 (دفعة مقدمة)، أعلام KSA-2 الأخرى (تصدير، ملخّصة، اسمية، بالنيابة، ذاتية)، **جهاز لكل فرع** (اليوم جهاز واحد للمنشأة)، عامل إبلاغ دائم بدل المسح داخل العملية، **تشغيل SDK الهيئة في CI**، التحقق الحي على بيئة المطورين (لم يتم لتعذّر DNS)، تجديد الشهادة، PDF/A-3.
### المرحلة 6: الموارد البشرية والرواتب — **غير موجود**
- لا جداول موظفين/حضور/مسير. توجد فقط حسابات في الدليل: سلف الموظفين 1109، رواتب مستحقة 2105، GOSI مستحقة 2106، مخصص نهاية الخدمة 2201، مصروف GOSI 6102، مصروف نهاية الخدمة 6113. مستقلة عن القطاع (تفيد المطاعم أيضاً).
### المرحلة 7: التقارير — **المالية موجودة**، والمخزون جزئياً، والإنتاج والرواتب لا.
### المرحلة 8: التصليب — Dockerfile وnginx موجودة في `deploy/`، لا CI، لا MFA، الأدوار غير مقيّدة بفرع.

## 4. الأنماط التي سألتزم بها
1. migration جديدة لكل تغيير (لا تعديل لما طُبّق)، وكل جدول: `tenant_id` أول الفهارس، RLS، منح `munassiq_app` بأقل صلاحية، triggers للإضافة فقط على الجداول المالية.
2. المسارات تحت `/api/v1/t` بـ `requireTenant("page.action")`، GET داخل `READ ONLY`، كل كتابة مالية في معاملة واحدة بـ `Idempotency-Key`، والقيد يُرحَّل في نفس المعاملة عبر دالة في `posting.ts` مضافة لـ `SOURCES`.
3. الحساب في الخادم فقط؛ المتصفح يرسل معرّفات وكميات.
4. الصلاحيات تُضاف في `CATALOG` ونسختها في الويب، مع اختبار التزامن الموجود.
5. الشاشات: `ResourcePage` للقوائم البسيطة، حالات التحميل والفراغ والخطأ والنجاح، حذف بتأكيد والتركيز على «إلغاء»، ⃁ للعملة، مهارات UX المذكورة في `CLAUDE.md`.
6. كل قيمة تنظيمية (GOSI، الاستقطاع، حد زاتكا) جدول بتاريخ سريان يقرؤه كود فعلي، مع مرجع المصدر.
7. قبل إعلان أي مرحلة: `npm test` و`npm run test:integration` و`typecheck` للطرفين و`build`، وذكر ما لم يُختبر.

## 5. تعارضات الملف مع المشروع (أوصي بالتزام المشروع)
| الملف يقول | المشروع يفرض | التوصية |
|---|---|---|
| Prisma/Drizzle/TypeORM | `pg` بلا ORM | `pg` |
| BullMQ | لا Redis | جدول مهام في PostgreSQL + عامل داخل العملية (`FOR UPDATE SKIP LOCKED`) |
| decimal.js | هللات صحيحة | الإبقاء على `money.ts`، وإضافة دوال كميات بدقة 6 منازل |
| Testcontainers / Playwright | قاعدة محلية + node:test | الإبقاء، وPlaywright لاحقاً في المرحلة 8 |
| وحدات منفصلة بـ Domain Events + Outbox | Monolith بمسارات ودوال ترحيل في نفس المعاملة | نفس المعاملة (أقوى اتساقاً)؛ Outbox فقط لما يخرج للخارج (زاتكا) |
| عربي/إنجليزي LTR | عربي RTL فقط | قرار مطلوب (انظر ARCHITECTURE.md) |
